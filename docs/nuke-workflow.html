Nuke Workflow & Render Discovery

A reference scaffold for robust file and render discovery in Nuke-oriented production workflows.

Flexible folder discovery

Do not assume one exact folder spelling. A production scanner may need to recognize common render directory names such as render, renders, HD_Renders, HDRenders, HDrenders, HD_Render, HDRender and HDrender.

Recommended scanning strategy

  1. Normalize folder names for case-insensitive comparison.
  2. Use an explicit allowlist of recognized names.
  3. Search recursively when the expected folder can be nested.
  4. Return all matching directories rather than stopping at the first result.
  5. Validate sequence frame ranges separately from directory discovery.

Production diagnostics

When no expected folder is found, report the searched root, expected names and directories inspected. Avoid silently treating a missing render as a valid empty sequence.

Nuke integration notes

Keep filesystem discovery in a testable Python module independent of Nuke where possible. Pass discovered sequences into Nuke-specific node creation only after paths and frame ranges have been validated.

Documentation is a living reference. Verify tool version, production environment and release notes before using any workflow on production data.
